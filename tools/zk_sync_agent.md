# ربط أجهزة البصمة ZKTeco بالنظام

النظام يدعم ثلاث طرق لسحب سجلات البصمة وتحويلها إلى سجلات حضور تُحتسب منها الرواتب.

---

## 1) ربط الموظف بالجهاز

في صفحة **أجهزة البصمة** ← تبويب **ربط الموظفين**:

- الرقم المسجّل في جهاز البصمة (PIN / User ID) يجب أن يساوي **كود الموظف** في النظام.
- إذا اختلف الرقمان، اكتب رقم الجهاز في خانة «رقم البصمة» للموظف وسيُحفظ في `employees.biometric_pin`.
- تُربط البطاقة (`card_number`) تلقائياً إن كان رقمها مسجلاً في النظام.

الأرقام غير المرتبطة تظهر في تبويب **سجلات البصمة** باللون الأحمر.

---

## 2) طريقة (أ): الوكيل المحلي على كم المكتب  ← *الأنسب لجهازك*

يعمل على نفس شبكة جهاز البصمة (الجهاز موصول بالراوتر أو مباشرة بالكمبيوتر).

### التثبيت
```bat
pip install pyzk requests
```

### سحب وإرسال مرة واحدة
```bat
python tools\zk_sync_agent.py --ip 192.168.1.201 --port 4370 --password 123 ^
  --server https://your-site.onrender.com --api-key SECRET ^
  --serial SN123456 --device-name "جهاز البصمة الرئيسي"
```

### تشغيل مستمر (كل 5 دقائق)
```bat
python tools\zk_sync_agent.py --ip 192.168.1.201 --password 123 ^
  --server https://your-site.onrender.com --api-key SECRET ^
  --serial SN123456 --loop --interval 5
```

### سحب فقط إلى ملفات CSV
```bat
python tools\zk_sync_agent.py --ip 192.168.1.201 --out C:\zklogs
```

> `SECRET` هو نفس قيمة **مفتاح استقبال السجلات** في تبويب **الإعدادات** داخل صفحة أجهزة البصمة
> (اتركه فارغاً للسماح بالاستقبال بدون مفتاح).

---

## 3) طريقة (ب): الدفع من الجهاز (ADMS / ICLOCK)

تعتمد على إعدادات الاتصال داخل جهاز ZKTeco نفسه:

| الإعداد في الجهاز | القيمة |
|---|---|
| Comm → ADMS → Server Address | `https://your-site.onrender.com/api/biometric/iclock/cdata` |
| Server Port | `80` أو `443` |
| Enable ADMS / Cloud Server | مفعّل |
| (اختياري) Request Interval | `5` |

عندها يدفع الجهاز السجلات تلقائياً إلى الخادم. المسارات التي يبحث عنها الجهاز:

- `/api/biometric/iclock/heartbeat` — نبض الاتصال
- `/api/biometric/iclock/cdata` — إرسال السجلات
- `/api/biometric/iclock/getrequest` — أوامر الخادم للجهاز
- `/api/biometric/iclock/devicecmd` — تنفيذ الأوامر

---

## 4) طريقة (ج): استيراد ملف (CSV / Excel)

من برنامج **ZKTimeWeb**: `Report → Attendance Records → Export` (CSV أو Excel)، ثم:

- صفحة **أجهزة البصمة** ← تبويب **استيراد ملف** ← اختر الملف ← **استيراد**.

الأعمدة التي يتعرف عليها النظام تلقائياً (بالإنجليزية أو العربية):

| النوع | الأسماء المدعومة |
|---|---|
| رقم الموظف | `PIN`, `User ID`, `Employee Code`, `Code`, `Card`, `رقم`, `كود` |
| التاريخ | `Date`, `Day`, `تاريخ` |
| الدخول | `Time In`, `Check In`, `In`, `Login`, `دخول` |
| الخروج | `Time Out`, `Check Out`, `Out`, `Logout`, `خروج` |
| النوع | `Status`, `الحالة` |

بعد الاستيراد: **معالجة وتحويل للحضور** من تبويب **سجلات البصمة**.

---

## 5) تحويل السجلات إلى حضور

- **معالجة وتحويل للحضور**: يحوّل السجلات الخام إلى سجلات `attendances` (حاضر/متأخر/غياب).
  - التأخير يُحسب بناءً على **بداية الدوام** + **مهلة التأخير** من تبويب **الإعدادات**.
  - الأيام التي فيها إجازة معتمدة لا تُمس.
  - `skip_existing = true` + `overwrite_status = true`: التحديث يحدّث الحالة مع الحفاظ على الأوقات المسجلة يدوياً.
- **تسجيل غياب**: ينشئ سجلات غياب لكل الموظفين في فترة محددة للأيام بلا بصمة وبلا إجازة (يتجاهل الجمعة إن كانت ضمن `work_days`).

---

## 6) ملاحظات ومشكلات شائعة

| المشكلة | الحل |
|---|---|
| `تعذر الاتصال بالجهاز` | تأكد من IP والمنفذ (4370 افتراضي) وكلمة المرور، وأن الجهاز والكمبيوتر على نفس الشبكة |
| `مكتبة pyzk غير مثبتة` | `pip install pyzk` أو استخدم ملف CSV/ADMS |
| السجلات لا تتحول | اضغط **معالجة وتحويل للحضور**، وتأكد من عدم وجود إجازة معتمدة بنفس اليوم |
| أرقام غير مرتبطة | اربطها من تبويب **ربط الموظفين** (الرقم في الجهاز = كود الموظف) |
| الجهاز على شبكة أخرى | استخدم IP ثابتاً للجهاز أو اربطه بالإنترنت (Cloud Server / ADMS) |
